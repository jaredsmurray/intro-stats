# Chapter writer brief template

Use this template selectively. Delete headings that do not apply.

## Writer brief: [chapter or section]

State the unit of work, audience, source artifact, major requested changes, and exact output path.

## 0. Access rules

List every readable file by absolute path and its allowed role. Prohibit neighboring drafts and unlisted book files. For book-aware work, authorize only the smallest relevant chapter set.

## 1. Source authority

| Dimension | Controlling source |
|---|---|
| User changes and exclusions | [request] |
| Content spine | [deck, outline, notes] |
| Empirical facts | [scripts and data] |
| Voice | [voice pack and applicable style skill] |
| Continuity | [selected current chapters] |

Add a `Do not import` list for tempting nearby material, unwanted examples, or inherited prose habits.

## 2. Audience and prior coverage

Record what readers already know, which datasets are new or familiar, which variables are new, and which backward links replace reteaching.

## 3. Content progression

Describe the ordered teaching moves. For each move, specify the question, example, required interpretation, and requested departure from the source artifact. Separate required content from optional elaboration.

## 4. Examples and empirical checks

Specify data files, filters, model equations, reference categories, comparison values, intervals, and approximate check results. Require the writer to recompute empirical values.

## 5. Visualizations and diagnostics

Inventory each required appearance with its teaching purpose and placement. State what must remain unchanged, what may be scaled or restyled, and which automatic plotting tools or diagnostic forms are prohibited.

## 6. Prose boundaries

Require the voice pack and surface skill. State that existing book prose controls continuity but not sentence style, density, or scope. Name recurring habits to avoid: extra coverage, repeated claims, post-figure recaps, duplicated caveats, and generic conclusions.

## 7. Quarto and implementation conventions

Specify YAML, setup chunks, hidden computation, labels, captions, tables, inline values, citation behavior, language independence, and project-root execution.

## 8. Verification

Require empirical execution, cross-reference checks, brief compliance, voice audit, redundancy audit, and confirmation that no unauthorized files changed.

## 9. Output contract

Name the only writable output file. Specify the final response: path, prose word count, and deliberate deviations or unresolved issues.
